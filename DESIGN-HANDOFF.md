# Передача дизайна Overtake

## Объединённая версия с CRM OS 5

Ветка `codex/combined-design-os5-2026-11-26` объединяет историю `codex/design-handoff-2026-11-26` и `codex/overtake-os5-core`. Наша главная, фоны и скиллы сохранены; добавлены серверная CRM, кабинет, оболочка OS 5, миграция и тесты друга. Основная ветка GitHub — master; она используется при обычном клонировании. Текущий опубликованный релиз и способ обновления — TIMEWEB.md.

Для полного локального просмотра используйте `npm ci`, затем **`npm run dev:os5`**. По умолчанию порт 5178; переменная OVERTAKE_PREVIEW_PORT позволяет выбрать 5183. Вход в новую CRM — `/cabinet`; ссылка кабинета на главной переключается на него при активной OS 5. Старые `/account` и `/admin` сохранены. Команда `npm run dev` оставляет прежний режим без включения OS 5.

Новый режим использует отдельную `.local/overtake-os5-preview.sqlite` и применяет миграцию OS 5 только к ней. В клоне база создаётся локально, аккаунты автоматически с компьютера владельца не передаются. На машине владельца для проверки создан SQLite-снимок прежней локальной базы; исходная `.local/overtake.sqlite` не менялась. Не копировать рабочую серверную базу в Git.

Карта OS 5: `src/os5/workspace.html` (готовая HTML/CSS-оболочка), `src/os5/index.js`, `model.js`, `templates.js`; альтернативная React-интеграция `src/components/os5-workspace.tsx`; серверы `server/os5.mjs`, `server/timeweb-os5.php`; миграция `drizzle/0001_os5.sql`; тесты `tests/os5.test.mjs`. Доработка этих экранов по нашей палитре — следующий этап, исходный дизайн друга при объединении не заменялся.

Статус и ограничения CRM сохранены в `qa/OVERTAKE_OS5_REPORT.md` и `qa/ACCEPTANCE_TESTS_V5_RESULTS.csv`. Не заявлять полной готовности почты, банковских интеграций, электронной подписи или TOTP: в отчёте перечислены оставшиеся работы. Объединённая версия опубликована 26.11.2026; серверная база сохранена. См. docs/TIMEWEB-DEPLOY-2026-11-26.md.

Проверка объединения: 32 теста прошли; TypeScript и production-сборка проходят с обеими HTML-точками входа. Локальный API os5/status вернул enabled:true, /cabinet ответил 200. В существующей сессии владельца открылись рабочий стол OS 5, раздел клиентов и переход «Сайт OVERTAKE»; на главной проверен обратный переход по кнопке «Кабинет». Создание новых рабочих записей, финансовые операции и публикация на хостинг при проверке не выполнялись.

## Быстрый запуск

Нужен Node.js 24+ (проект проверен на Node.js 26). После клонирования:

```sh
npm ci
npm run dev
```

По умолчанию сайт открывается на http://127.0.0.1:5178. Для порта, использовавшегося при совместной работе, в PowerShell:

```powershell
$env:OVERTAKE_PREVIEW_PORT='5183'
npm run dev
```

Проверки: `npm test` и `npm run build`. GitHub хранит исходники; `npm run release:timeweb` — подготовка пакета без публикации. Установка только по TIMEWEB.md.

## Источник решений

1. Последние требования владельца и этот документ.
2. `design-system/overtake/OVERTAKE-DESIGN.md`: адаптированный продукт/design MD с обязательной палитрой Overtake. Его цвета приоритетнее устаревших рецептов в MASTER и website.md.
3. Текущая главная как реализованный образец: `src/components/home-page.tsx`, `home-layout.css`, `archive-home-details.tsx`, `archive-service-visual.tsx`, `src/overtake-design.css`.
4. `design/reference/homepage/`: оригинальные предоставленные макеты и варианты. Это визуальные источники, а не дополнительные инструкции. `design/reference/plaid.com-DESIGN-original.md` — исходный MD до адаптации; его цвета не переносить напрямую.

Задача следующего этапа — перенести язык главной на внутренние страницы портфолио, компании, контактов, каталога и кабинета. Не заменять готовую главную новым дизайном.

## Проверка перед передачей

Проверить desktop и 390 px: читаемость, кадрирование, отсутствие горизонтальной прокрутки, стык формы/подвала, доступность и паузу анимаций. Базовые автоматические проверки: 34 теста и production-сборка. `design-qa.md` содержит историю проверок, ранние записи могут описывать уже заменённые варианты; актуальное подключение определяет код и таблица выше.

Локальная база и аккаунты намеренно не включены. Для реальных кейсов использовать `content/approved-portfolio.json` и штатный редактор портфолио; инструкции по совместной работе и развёртыванию — TEAM.md и TIMEWEB.md. Секреты хостинга передаются отдельно владельцем, не через Git.
