# Перенос OVERTAKE на Timeweb

Подготовлен вариант для виртуального хостинга PHP 8.2+ с PDO SQLite и mbstring. React-интерфейс сохранён. PHP реализует тот же API для регистрации, сессий, кабинетов, заявок, сообщений, калькулятора, профиля и администрирования. Не реализованные ранее почтовое восстановление, платежи и файловые документы не становятся подключёнными после переноса.

## Текущее состояние

Загрузка через браузер дважды отклонена системой разрешений. В аккаунте создана пустая папка `overtake`. Домен `helmerzy.tw1.ru` пока связан с DEALORE, старые файлы не изменены. Публичная исходная версия остаётся на Sites. Старая база проверена: пользователей, заявок, сообщений, расчётов и записей контента на момент подготовки нет.

## Пакет

`.local/overtake-timeweb.zip` — готовый пакет первоначальной установки. **Содержит секреты развёртывания и администратора. Не публиковать и не коммитить.**

Распаковать в `/overtake`, а не в `public_html`. Получится:

```
overtake/
  public_html/            # корень нового сайта
    .htaccess
    index.php
    _overtake-deploy.php
  overtake-private/       # вне публичного корня
    config.json
    schema.sql
    current
    releases/<version>/
      api.php
      client/index.html
      client/assets/...
```

В панели «Сайты» создать сайт с корнем `overtake/public_html`, PHP 8.2+, затем перепривязать `helmerzy.tw1.ru` с DEALORE. Файлы `/dealore` оставить для отката. Проверить сертификат и HTTPS. Подготовленный пакет требует подтверждения доступности PDO SQLite и mbstring непосредственно на Timeweb; это пока не проверено из-за блокировки загрузки.

`GET /api/health` проверяет работу PHP, базы и активной версии. Проверить регистрацию двух клиентов, изоляцию заявок, переписку, административный калькулятор и сохранение данных после обновления. Только после успешной проверки переключённого сайта считать перенос завершённым.

## Обновления

После первой установки:

```
npm run publish:timeweb
npm run sync:timeweb
```

Первая команда запускает тесты, сборку и публикацию. Вторая следит за исходниками на этом компьютере; после изменения выполняет тот же цикл. Должна оставаться запущенной для автоматических обновлений. При ошибках тестов/сборки/загрузки старый сайт продолжает работать. После первого успешного развёртывания можно запускать её в фоновом режиме.

Публикация подписана HMAC-SHA256, запрос ограничен временем и одноразовым nonce. Секрет хранится в игнорируемом `.local/timeweb-config.json`. Обновляются только разрешённые файлы приложения. Версия сначала записывается в новый каталог, затем атомарно переключается файл `current`. SQLite и конфигурация остаются вне релизов и не перезаписываются. Старые версии сохраняются для отката. Не передавать секрет в URL, Git, скриншотах или журнале.

Изменения bootstrap-файлов `timeweb-index.php` и `timeweb-deploy.php` требуют отдельной установки; обычная публикация обновляет React и `timeweb-api.php`.
