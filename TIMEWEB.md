# Обновление действующего Timeweb

Сайт: https://helmerzy.tw1.ru/. Основная ветка — master. Опубликованная база: релиз 6ade4c5a7817e579, исходники 36bef6b. См. docs/TIMEWEB-DEPLOY-2026-11-26.md.

## Только приложение

Обновляется полная согласованная сборка кода: api.php, client/index.html, client/assets/*. Она записывается в новый релиз; затем атомарно переключается current. Пользователи, заявки, конфиг и ключи в пакет не входят. Не копировать репозиторий целиком в public_html и не использовать синхронизацию с удалением серверных файлов.

Существующие overtake-private/data.sqlite, config.json, schema.sql, документы и вложения сохраняются. Генератор не создаёт базу, ключи или администратора. Изменения схемы требуют отдельного плана миграции; дизайн не повод подменять базу.

Для релиза с воронкой лидов требуется `drizzle/0002_os5_lead_workflow.sql`. До активации проверить миграцию на свежей копии базы, сделать SQLite-снимок рабочей базы и применить SQL к существующей базе одной транзакцией с включёнными внешними ключами. Сверить `PRAGMA quick_check` и `PRAGMA foreign_key_check`. Миграция добавляет таблицу и триггеры без переноса или замены заявок. При откате кода таблицу сохранять.

## Подготовка

1. Получить свежую master: git fetch origin, git pull --ff-only. Объединить изменения коллег, проверить и сохранить согласованный коммит в GitHub. Старый checkout нельзя публиковать поверх нового.
2. npm ci.
3. npm run release:timeweb — тесты, TypeScript, сборка, чтение /api/health и фиксация текущего серверного релиза. Команда НЕ публикует сайт.
4. В .local/timeweb-update/ появятся overtake-release-<id>.json, activate-<id>.php, README.txt. Брать только пару JSON/PHP с одним ID из последней подготовки.

## Установка по запросу владельца

Нужен доступ к существующему Timeweb. Секреты в Git не передаются.

1. Загрузить выбранные JSON и PHP в /home/h/helmerzy/overtake/ — вне public_html.
2. В SSH-консоли проверить: php -l /home/h/helmerzy/overtake/activate-<id>.php.
3. Запустить: php /home/h/helmerzy/overtake/activate-<id>.php.
4. Проверить сообщение Activated <id>, совпадение release в /api/health, главную, изображения, внутренние страницы и вход /cabinet. Авторизованные CRM-действия проверять отдельно с разрешённым аккаунтом.

Активатор сверяет SHA-256 пакета и записанных файлов, ограничивает пути, блокирует параллельное развёртывание, сохраняет SQLite-снимок и прежние current/index.php. Если сервер обновился после подготовки, выполнение прекращается до записи релиза и переключения. Нужно объединить свежий код и подготовить новую пару. Эта защита не заменяет git pull и ревью.

Маршрутизатор из server/timeweb-index.php обновляется вместе с приложением; PNG/WebP поддерживаются. .htaccess и конфигурация не заменяются. Старый HTTP-обработчик ограничен 8 МБ; нынешние фоны превышают лимит. Старые автоматическая публикация, watcher и первичные установочные пакеты выведены из рабочего процесса.

## Откат

В overtake-private/backup-<timestamp>-<suffix> находятся current, index.php и SQLite-снимок. При проблеме с кодом вернуть предыдущий current и router из этой пары. Предыдущий релиз сохраняется. Базу при откате интерфейса не восстанавливать: это удалит новые записи. Восстановление базы согласуется отдельно.

15 предыдущих релизов находятся в закрытом archived-releases-20261126. Для отката на них сначала вернуть каталог нужного ID в releases. Архивы не входят в Git.
